:::note[Concept only]
Tallyfy has no integration or partnership with Unitree Robotics, and it doesn't sell a Unitree connector. This page is a concept. It describes how the two could work together if your own developer built the link. Vendor facts are as of October 2026.

## Where a Tallyfy process fits beside Unitree robots

[Unitree Robotics](https://www.unitree.com/about/)<a href="https://www.unitree.com/about/" rel="nofollow noopener noreferrer" target="_blank"><sup>[1]</sup></a> builds four-legged and humanoid robots. Some [inspect sites such as substations and refineries](https://www.unitree.com/industry/electricity/)<a href="https://www.unitree.com/industry/electricity/" rel="nofollow noopener noreferrer" target="_blank"><sup>[2]</sup></a>, and send their readings to a control center. Tallyfy could track what your people do next: who checks an odd reading, who signs it off, and by when.

Nothing connects the two today. Your developer would write a small program that runs beside the robot and talks to both. Unitree also sells its own inspection system, [covered below](#what-unitree-already-covers).

## What Unitree sells, and which editions you can program

The model names here are Unitree's own, as of October 2026. Only some editions accept outside software, which Unitree calls "secondary development".

Four-legged robots:

- [Go2](https://www.unitree.com/go2/)<a href="https://www.unitree.com/go2/" rel="nofollow noopener noreferrer" target="_blank"><sup>[3]</sup></a> is a consumer and education model, sold as AIR, PRO, X and EDU. The EDU is programmable, and the X partly.
- [As2](https://www.unitree.com/As2/)<a href="https://www.unitree.com/As2/" rel="nofollow noopener noreferrer" target="_blank"><sup>[4]</sup></a> comes in the same four editions. The X and EDU are programmable.
- [B2](https://www.unitree.com/b2/)<a href="https://www.unitree.com/b2/" rel="nofollow noopener noreferrer" target="_blank"><sup>[5]</sup></a> is an industrial model for inspection and rescue work. There's an explosion-proof [B2-Ex](https://www.unitree.com/B2-Ex/)<a href="https://www.unitree.com/B2-Ex/" rel="nofollow noopener noreferrer" target="_blank"><sup>[6]</sup></a> too.
- [A2](https://www.unitree.com/A2/)<a href="https://www.unitree.com/A2/" rel="nofollow noopener noreferrer" target="_blank"><sup>[7]</sup></a> is a programmable industrial model for logistics, inspection and rescue. It carries about 25kg while walking, or about 100kg standing still.
- Wheeled versions are the [Go2-W](https://www.unitree.com/go2-w/)<a href="https://www.unitree.com/go2-w/" rel="nofollow noopener noreferrer" target="_blank"><sup>[8]</sup></a>, [As2-W](https://www.unitree.com/As2-W/)<a href="https://www.unitree.com/As2-W/" rel="nofollow noopener noreferrer" target="_blank"><sup>[9]</sup></a>, [B2-W](https://www.unitree.com/b2-w/)<a href="https://www.unitree.com/b2-w/" rel="nofollow noopener noreferrer" target="_blank"><sup>[10]</sup></a> and [A2-W](https://www.unitree.com/A2-W/)<a href="https://www.unitree.com/A2-W/" rel="nofollow noopener noreferrer" target="_blank"><sup>[11]</sup></a>.

Humanoid robots:

## What outside software can and can't do

On a programmable edition, your own program can use Unitree's developer kit (SDK). It can read the robot's state, such as [battery voltage](https://github.com/unitreerobotics/unitree_sdk2_python)<a href="https://github.com/unitreerobotics/unitree_sdk2_python" rel="nofollow noopener noreferrer" target="_blank"><sup>[25]</sup></a> or [position and speed](https://github.com/unitreerobotics/unitree_ros2)<a href="https://github.com/unitreerobotics/unitree_ros2" rel="nofollow noopener noreferrer" target="_blank"><sup>[26]</sup></a>. It can also send movement commands. On the Go2 those include [move at a set speed, stand up, sit and stop](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py)<a href="https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py" rel="nofollow noopener noreferrer" target="_blank"><sup>[27]</sup></a>.

As of October 2026, the SDK has two limits:

- **No calls from the internet.** The SDK reaches the robot over [the robot's own network](https://github.com/unitreerobotics/unitree_sdk2_python)<a href="https://github.com/unitreerobotics/unitree_sdk2_python" rel="nofollow noopener noreferrer" target="_blank"><sup>[28]</sup></a>, and its GitHub pages describe no web interface. Unitree doesn't say so itself, but that means a cloud service such as Tallyfy can't call a robot directly. A program beside the robot has to make every call.
- **No single call for a whole job.** The [Python SDK](https://github.com/unitreerobotics/unitree_sdk2_python)<a href="https://github.com/unitreerobotics/unitree_sdk2_python" rel="nofollow noopener noreferrer" target="_blank"><sup>[29]</sup></a> describes movement and service calls, so your program has to break a job into those. In July 2026 Unitree added a separate [navigation interface](https://github.com/unitreerobotics/unitree_slam)<a href="https://github.com/unitreerobotics/unitree_slam" rel="nofollow noopener noreferrer" target="_blank"><sup>[30]</sup></a> with [example scripts](https://github.com/unitreerobotics/Python_unitree_demos)<a href="https://github.com/unitreerobotics/Python_unitree_demos" rel="nofollow noopener noreferrer" target="_blank"><sup>[31]</sup></a> such as MoveToAction and GoHomeAction.

## What Unitree already covers

Unitree sells an [inspection system](https://www.unitree.com/industry/electricity/)<a href="https://www.unitree.com/industry/electricity/" rel="nofollow noopener noreferrer" target="_blank"><sup>[32]</sup></a> for the B2, B2-Ex, A2 and As2. As of October 2026, Unitree says it:

- Runs scheduled inspections on its own, with remote manual control.
- Schedules several robots from one place.
- Writes inspection reports and keeps past data to compare.

Unitree also has an app platform called [UniStore](https://github.com/unitreerobotics/unitree-app-templates)<a href="https://github.com/unitreerobotics/unitree-app-templates" rel="nofollow noopener noreferrer" target="_blank"><sup>[33]</sup></a>, and it sends [software updates over the air](https://www.unitree.com/g1/)<a href="https://www.unitree.com/g1/" rel="nofollow noopener noreferrer" target="_blank"><sup>[34]</sup></a>.

If scheduled rounds and reports are all you need, Unitree's system covers them without Tallyfy.

## Where Tallyfy could fit

Unitree's tools run the robot. Tallyfy tracks work that people do.

Say a robot reads a high temperature on its round. Your program could [launch a Tallyfy process](/products/pro/launching/triggers/via-api/) from a [template](/products/pro/documenting/templates/) you wrote for that case. Tallyfy then assigns each task to a person with a deadline, collects what they find in [form fields](/products/pro/tracking-and-tasks/tasks/what-are-form-fields-in-tallyfy/), and shows progress in the [Tracker view](/products/pro/tracking-and-tasks/tracker-view/).

When the procedure changes, you edit the template once. Every process launched after that uses the new steps.

This diagram follows one finding from the robot to your team.

```d2
# One robot finding becomes tracked work for people
direction: down

Site: Your site {
  style.stroke: "#225930"
  style.stroke-dash: 3

  Robot: Unitree robot {
    style.fill: "#e1f7e6"
    style.stroke: "#225930"
  }

  Program: Your own program {
    style.fill: "#f2faf4"
    style.stroke: "#225930"
  }
}

Tallyfy: Tallyfy {
  style.stroke: "#225930"
  style.stroke-dash: 3

  Process: Process starts {
    style.fill: "#f2faf4"
    style.stroke: "#225930"
  }

  Tasks: Tasks for people {
    style.fill: "#f2faf4"
    style.stroke: "#225930"
  }

  Done: Finding closed {
    shape: circle
    style.fill: "#e1f7e6"
    style.stroke: "#225930"
    style.stroke-width: 2
  }
}

Site.Robot -> Site.Program: Shares readings
Site.Program -> Tallyfy.Process: Calls Tallyfy API
Tallyfy.Process -> Tallyfy.Tasks: Assigns people
Tallyfy.Tasks -> Tallyfy.Done: People finish
```

**What to notice:**
- Only your own program talks to the robot.
- Tallyfy starts work for people. It doesn't steer the robot.
- The program and the template are yours to build and maintain.

## For developers

*(Skip this unless you're setting up the technical side.)*

This section is an example. Tallyfy doesn't publish or support a Unitree connector, and the code is an untested sketch.

As of October 2026, Unitree's SDKs are on GitHub:

- [unitree_sdk2](https://github.com/unitreerobotics/unitree_sdk2)<a href="https://github.com/unitreerobotics/unitree_sdk2" rel="nofollow noopener noreferrer" target="_blank"><sup>[35]</sup></a> is the C++ SDK, [built on CycloneDDS](https://github.com/unitreerobotics/unitree_ros2)<a href="https://github.com/unitreerobotics/unitree_ros2" rel="nofollow noopener noreferrer" target="_blank"><sup>[36]</sup></a>. Its [example folders](https://github.com/unitreerobotics/unitree_sdk2/tree/main/example)<a href="https://github.com/unitreerobotics/unitree_sdk2/tree/main/example" rel="nofollow noopener noreferrer" target="_blank"><sup>[37]</sup></a> cover a2, as2, b2, b2w, g1, go2, go2w, h1, h2 and r1.
- [unitree_sdk2_python](https://github.com/unitreerobotics/unitree_sdk2_python)<a href="https://github.com/unitreerobotics/unitree_sdk2_python" rel="nofollow noopener noreferrer" target="_blank"><sup>[38]</sup></a> needs Python 3.8 or later and imports as [`unitree_sdk2py`](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/setup.py)<a href="https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/setup.py" rel="nofollow noopener noreferrer" target="_blank"><sup>[39]</sup></a>.
- [unitree_ros2](https://github.com/unitreerobotics/unitree_ros2)<a href="https://github.com/unitreerobotics/unitree_ros2" rel="nofollow noopener noreferrer" target="_blank"><sup>[40]</sup></a> is for ROS 2, tested on foxy and humble.
- [unitree_legged_sdk](https://github.com/unitreerobotics/unitree_legged_sdk)<a href="https://github.com/unitreerobotics/unitree_legged_sdk" rel="nofollow noopener noreferrer" target="_blank"><sup>[41]</sup></a> is the older SDK for the Go1 generation. Skip it for the models above.

The Go2 takes high-level commands through [`SportClient`](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py)<a href="https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/go2/sport/sport_client.py" rel="nofollow noopener noreferrer" target="_blank"><sup>[42]</sup></a>, with calls such as `Move(vx, vy, vyaw)`, `StandUp`, `Sit` and `StopMove`. The G1 humanoid uses [`LocoClient`](https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/g1/loco/g1_loco_client.py)<a href="https://github.com/unitreerobotics/unitree_sdk2_python/blob/master/unitree_sdk2py/g1/loco/g1_loco_client.py" rel="nofollow noopener noreferrer" target="_blank"><sup>[43]</sup></a>.

Unitree's examples run from a computer [connected to the robot's network](https://github.com/unitreerobotics/unitree_sdk2_python)<a href="https://github.com/unitreerobotics/unitree_sdk2_python" rel="nofollow noopener noreferrer" target="_blank"><sup>[44]</sup></a>. Yours also needs internet access to reach Tallyfy. Use a Tallyfy [API](/products/pro/integrations/open-api/) application token, because a personal token stops working when that user logs out.

This sketch stops a Go2 and launches a Tallyfy process. It leaves out the `SportClient` setup, which Unitree's examples show.

```python
# Example only: an untested sketch. Tallyfy doesn't ship a Unitree connector.
import os

import requests
from unitree_sdk2py.go2.sport.sport_client import SportClient

ORG_ID = os.environ["TALLYFY_ORG_ID"]
ACCESS_TOKEN = os.environ["TALLYFY_ACCESS_TOKEN"]
TEMPLATE_ID = "TEMPLATE_ID_TO_LAUNCH"
READING_FIELD_ID = "KICKOFF_FIELD_TIMELINE_ID"


def hand_over_to_people(sport_client: SportClient, reading: str) -> str:
    """Stop the Go2, then launch a Tallyfy process for the finding.

    Pass in a SportClient you've already set up. That setup isn't shown.
    """
    sport_client.StopMove()

    response = requests.post(
        f"https://go.tallyfy.com/api/organizations/{ORG_ID}/runs",
        headers={
            "Authorization": f"Bearer {ACCESS_TOKEN}",
            "Accept": "application/json",
            "X-Tallyfy-Client": "APIClient",
            "Content-Type": "application/json",
        },
        json={
            "checklist_id": TEMPLATE_ID,
            "name": "Robot finding - substation round",
            "prerun": {READING_FIELD_ID: reading},
        },
        timeout=15,
    )
    response.raise_for_status()
    return response.json()["data"]["id"]  # ID of the new process
```

The request is the standard [launch process](/products/pro/integrations/open-api/code-samples/processes/launch-process/) call, and each `prerun` key is a kick-off form field's timeline ID. [Update task](/products/pro/integrations/open-api/code-samples/tasks/update-task/) and [complete task](/products/pro/integrations/open-api/code-samples/tasks/complete-task/) write a result back and close the task.
