## How an ABB robot could start a Tallyfy procedure

ABB Robotics makes [industrial and collaborative robots, controllers and software](https://www.abb.com/global/en/areas/robotics)<a href="https://www.abb.com/global/en/areas/robotics" rel="nofollow noopener noreferrer" target="_blank"><sup>[1]</sup></a>. Its controllers answer to [Robot Web Services](https://developercenter.robotstudio.com/api/RWS)<a href="https://developercenter.robotstudio.com/api/RWS" rel="nofollow noopener noreferrer" target="_blank"><sup>[2]</sup></a>, a published API[^1] that lets other software start a robot program, read the controller's state and hear about changes as they happen. So when a robot stops with an error, your own software could start a written procedure in Tallyfy, with an owner and a deadline for each step.

Tallyfy doesn't sell that connection. Your team or your integrator would have to build it.

## What outside software can ask a robot to do

As of October 2026, ABB's [Robot Web Services 2.0 reference](https://developercenter.robotstudio.com/api/RWS)<a href="https://developercenter.robotstudio.com/api/RWS" rel="nofollow noopener noreferrer" target="_blank"><sup>[12]</sup></a> lets a program written in any language:

- Load a robot program, set the values it uses, then start, stop or reset it.
- Read whether the program is running, along with the controller's state and operating mode.
- Read the controller's event log.
- Switch an input or output signal on or off.
- Subscribe to changes. The controller sends each change at once, within 200 milliseconds, or within 5 seconds, depending on the priority the program picks. Only signals and saved program values (persistent RAPID variables) can use the fastest setting.

To start a robot program, your software has to log in with a user account set up on the controller and hold what ABB calls [mastership](https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/RAPID_Service.yaml)<a href="https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/RAPID_Service.yaml" rel="nofollow noopener noreferrer" target="_blank"><sup>[13]</sup></a>, the right to change what the controller is doing.

Factories that already use OPC UA[^2] can reach the same controllers through ABB's [IoT Gateway](https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway)<a href="https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway" rel="nofollow noopener noreferrer" target="_blank"><sup>[14]</sup></a>. It works with both IRC5 and OmniCore controllers.

## What outside software can't do

All four limits are as of October 2026.

- [Robot Web Services](https://developercenter.robotstudio.com/api/RWS)<a href="https://developercenter.robotstudio.com/api/RWS" rel="nofollow noopener noreferrer" target="_blank"><sup>[15]</sup></a> has no call for a whole fleet. Each call goes to one controller and works with the robot programs on it.
- Version 2.0 comes with RobotWare 7, which ships on OmniCore controllers, says ABB's [developer centre](https://developercenter.robotstudio.com/webservice)<a href="https://developercenter.robotstudio.com/webservice" rel="nofollow noopener noreferrer" target="_blank"><sup>[16]</sup></a>. Older RobotWare versions use version 1.0, which ABB marks as deprecated in RobotWare 7.
- ABB's older OPC server isn't recommended for new projects. The [developer centre](https://developercenter.robotstudio.com/opcserver-sdk)<a href="https://developercenter.robotstudio.com/opcserver-sdk" rel="nofollow noopener noreferrer" target="_blank"><sup>[17]</sup></a> points to the IoT Gateway instead.
- None of the eight tools on ABB's [developer centre](https://developercenter.robotstudio.com/)<a href="https://developercenter.robotstudio.com/" rel="nofollow noopener noreferrer" target="_blank"><sup>[18]</sup></a> is for ROS[^3]. Other groups publish open-source drivers.

Ask ABB or your integrator what your controller needs before you plan a connection.

## Where a written procedure in Tallyfy fits

A robot can report that it stopped. People still have to find the cause, fix it and sign off before it runs again. A Tallyfy [template](/products/pro/documenting/templates/) is the written procedure for that work: the steps, who does each one, and by when.

As a concept, a small connector your team writes would subscribe to the controller's events. When the controller logs an error, the connector would call Tallyfy's API to [launch the matching process](/products/pro/launching/triggers/via-api/) and copy the error into its kick-off form. Tallyfy would then assign the repair to named people. The last step can be an [approve/reject task](/products/pro/tracking-and-tasks/tasks/what-types-of-tasks-can-i-create-with-tallyfy/), so a supervisor decides whether the cell runs again. When it's approved, a Tallyfy webhook (a message Tallyfy sends to another system when something happens) could tell the connector. Whether software may restart a robot at all is a decision for your safety review.

You don't need a connector to begin. A person can type what the controller shows into a Tallyfy [form field](/products/pro/tracking-and-tasks/tasks/what-are-form-fields-in-tallyfy/).

## For developers

(Skip this unless you're setting up the technical side.)

- ABB's [developer centre](https://developercenter.robotstudio.com/webservice)<a href="https://developercenter.robotstudio.com/webservice" rel="nofollow noopener noreferrer" target="_blank"><sup>[19]</sup></a> says version 2.0 is OpenAPI compliant, so Swagger tools can generate client code.
- The [2.0 reference](https://developercenter.robotstudio.com/api/RWS)<a href="https://developercenter.robotstudio.com/api/RWS" rel="nofollow noopener noreferrer" target="_blank"><sup>[20]</sup></a> is ABB document 3HAC073675-001, Revision L. Clients log in with Basic authentication, as users set up in the controller. Events arrive over secure WebSockets, up to 10 per session, with 70 sessions in total.
- Calls behind the list above include [POST /rw/rapid/execution/start](https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/RAPID_Service.yaml)<a href="https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/RAPID_Service.yaml" rel="nofollow noopener noreferrer" target="_blank"><sup>[21]</sup></a>, [GET /rw/panel/ctrl-state](https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Panel_Service.yaml)<a href="https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Panel_Service.yaml" rel="nofollow noopener noreferrer" target="_blank"><sup>[22]</sup></a>, [GET /rw/elog](https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Elog_Service.yaml)<a href="https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Elog_Service.yaml" rel="nofollow noopener noreferrer" target="_blank"><sup>[23]</sup></a> and [POST /subscription](https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Subscription_Service.yaml)<a href="https://developercenter.robotstudio.com/api/RWS/Swagger_Doc/Subscription_Service.yaml" rel="nofollow noopener noreferrer" target="_blank"><sup>[24]</sup></a>.
- The [IoT Gateway](https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway)<a href="https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway" rel="nofollow noopener noreferrer" target="_blank"><sup>[25]</sup></a> also supports MQTT.
- Open-source projects, not ABB releases: [abb_robot_driver](https://github.com/ros-industrial/abb_robot_driver)<a href="https://github.com/ros-industrial/abb_robot_driver" rel="nofollow noopener noreferrer" target="_blank"><sup>[26]</sup></a>, a ROS driver, and [abb_librws](https://github.com/ros-industrial/abb_librws)<a href="https://github.com/ros-industrial/abb_librws" rel="nofollow noopener noreferrer" target="_blank"><sup>[27]</sup></a>, the C++ library it builds on, both from ROS-Industrial. abb_librws uses Robot Web Services 1.0 and doesn't work with RobotWare 7. There is also [abb_ros2](https://github.com/PickNikRobotics/abb_ros2)<a href="https://github.com/PickNikRobotics/abb_ros2" rel="nofollow noopener noreferrer" target="_blank"><sup>[28]</sup></a> from PickNik Robotics.
- On the Tallyfy side, the connector starts a process with `POST https://go.tallyfy.com/api/organizations/{org_id}/runs`. The [launch process reference](/products/pro/integrations/open-api/code-samples/processes/launch-process/) lists the headers and fields, and the [webhooks guide](/products/pro/integrations/webhooks/) covers the other direction.

[^1]: A published way for one program to talk to another and swap data, with nobody at a screen.
[^2]: An industry standard that lets machines and software from different makers share data securely.
[^3]: ROS (Robot Operating System) is open-source software that many robot developers build on.
