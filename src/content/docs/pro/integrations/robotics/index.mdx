Tallyfy has no integration or partnership with any robot maker, and nothing here is a product you can buy or switch on. These pages describe a concept and what each maker's own software can be asked to do. Vendor facts link to their source, read in October 2026.

## How a written procedure could drive robot work

Tallyfy runs the steps people follow. Write a procedure once as a [template](/products/pro/documenting/templates/), and each launch becomes a [process](/products/pro/tracking-and-tasks/processes/) with tasks, owners, deadlines and an [activity log](/products/pro/tracking-and-tasks/tracker-view/how-can-i-track-process-activities-on-tallyfy/) of who did what.

Some robot makers let outside software read a robot's status or send it work. Where they do, a small program your developer writes could join the two, so a robot fault launches the right Tallyfy process. Boston Dynamics describes the same idea for Spot: an application that [creates a work order whenever the robot finds an anomaly](https://dev.bostondynamics.com/docs/concepts/orbit/about_orbit)<a href="https://dev.bostondynamics.com/docs/concepts/orbit/about_orbit" rel="nofollow noopener noreferrer" target="_blank"><sup>[1]</sup></a>. Tallyfy doesn't build or ship that program.

## What a link would take

Your developer would need three things. The robot maker has to publish an interface, a documented way for a program to read the robot's status or send it work. Tallyfy's side exists today: another system can [launch a process through the API](/products/pro/launching/triggers/via-api/) or [complete a task](/products/pro/integrations/open-api/code-samples/tasks/complete-task/), and Tallyfy sends a webhook (a message to another system) when a [task is completed or a process launches](/products/pro/integrations/webhooks/).

The program has to reach both sides, so plan where it runs with your IT team. NIST's [guide to operational technology security](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-82r3.pdf)<a href="https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-82r3.pdf" rel="nofollow noopener noreferrer" target="_blank"><sup>[2]</sup></a> recommends keeping the networks that run physical equipment apart from the corporate network, with a buffer zone called a DMZ between them.

Before you buy, ask the robot maker in writing what your software may connect to. Some interfaces need an extra controller option, as [FANUC's driver does](https://fanuc-corporation.github.io/fanuc_driver_doc/main/docs/environment/system_requirements.html)<a href="https://fanuc-corporation.github.io/fanuc_driver_doc/main/docs/environment/system_requirements.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[3]</sup></a>.

## Where each robot maker stands

As of October 2026, these seven have a page of their own:

- [Apptronik Apollo humanoid robots](/products/pro/integrations/robotics/apptronik/) - Apptronik makes the [Apollo humanoid robot](https://apptronik.com/apollo/apollo-2)<a href="https://apptronik.com/apollo/apollo-2" rel="nofollow noopener noreferrer" target="_blank"><sup>[4]</sup></a>. It publishes no way for outside software to send it work or read its status, as an [independent API catalogue](https://github.com/api-evangelist/apptronik)<a href="https://github.com/api-evangelist/apptronik" rel="nofollow noopener noreferrer" target="_blank"><sup>[5]</sup></a> also found.
- [Boston Dynamics Spot, Stretch and Atlas](/products/pro/integrations/robotics/boston-dynamics/) - Boston Dynamics makes [Spot, a mobile robot for industrial inspection](https://bostondynamics.com/products/spot/)<a href="https://bostondynamics.com/products/spot/" rel="nofollow noopener noreferrer" target="_blank"><sup>[6]</sup></a>. Its [Orbit software](https://dev.bostondynamics.com/docs/concepts/orbit/about_orbit)<a href="https://dev.bostondynamics.com/docs/concepts/orbit/about_orbit" rel="nofollow noopener noreferrer" target="_blank"><sup>[7]</sup></a> lets outside software schedule Spot's missions, read the results and get a webhook when Spot completes an action.
- [Universal Robots collaborative arms](/products/pro/integrations/robotics/universal-robots/) - Universal Robots makes [collaborative robot arms, or cobots](https://www.universal-robots.com/insights/faq/)<a href="https://www.universal-robots.com/insights/faq/" rel="nofollow noopener noreferrer" target="_blank"><sup>[8]</sup></a>. Outside software can [start and stop a program](https://docs.universal-robots.com/PolyScopeX_SDK_Documentation/build/SDK-v0.22/Resources.html)<a href="https://docs.universal-robots.com/PolyScopeX_SDK_Documentation/build/SDK-v0.22/Resources.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[9]</sup></a> and [stream live robot data](https://docs.universal-robots.com/tutorials/communication-protocol-tutorials/rtde-guide.html)<a href="https://docs.universal-robots.com/tutorials/communication-protocol-tutorials/rtde-guide.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[10]</sup></a>.

Outside software can [read a robot's status over OPC UA](https://opcfoundation.org/products/view/kr-c5/)<a href="https://opcfoundation.org/products/view/kr-c5/" rel="nofollow noopener noreferrer" target="_blank"><sup>[12]</sup></a>, and can send work to a program on the controller through an add-on KUKA sells, such as [KUKA.Ethernet KRL](https://www.kuka.com/en-de/products/robot-systems/software/hub-technologies/kuka-ethernet-krl)<a href="https://www.kuka.com/en-de/products/robot-systems/software/hub-technologies/kuka-ethernet-krl" rel="nofollow noopener noreferrer" target="_blank"><sup>[13]</sup></a>.
- [Unitree quadruped and humanoid robots](/products/pro/integrations/robotics/unitree/) - Unitree makes [four-legged and humanoid robots](https://www.unitree.com/about/)<a href="https://www.unitree.com/about/" rel="nofollow noopener noreferrer" target="_blank"><sup>[14]</sup></a>. ## Safety standards for industrial robots

As of October 2026, the standards bodies list these editions of the industrial robot safety standards:

- **ISO 10218-1:2025**, Robotics - Safety requirements - Part 1: Industrial robots. [Edition 3, February 2025](https://www.iso.org/standard/73933.html)<a href="https://www.iso.org/standard/73933.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[33]</sup></a>.
- **ISO 10218-2:2025**, Robotics - Safety requirements - Part 2: Industrial robot applications and robot cells. [Edition 2, February 2025](https://www.iso.org/standard/73934.html)<a href="https://www.iso.org/standard/73934.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[34]</sup></a>.
- **ISO/TS 15066:2016**, Robots and robotic devices - Collaborative robots. [Edition 1, February 2016](https://www.iso.org/standard/62996.html)<a href="https://www.iso.org/standard/62996.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[35]</sup></a>, which ISO marked in June 2025 to be revised.
- **ANSI/A3 R15.06-2025**, the US safety standard for industrial robots. A3 [released it in September 2025](https://www.newequipment.com/product-news/automation/news/55315582/new-ansi-a3-r1506-2025-us-standard-updates-safety-rules-for-industrial-robots)<a href="https://www.newequipment.com/product-news/automation/news/55315582/new-ansi-a3-r1506-2025-us-standard-updates-safety-rules-for-industrial-robots" rel="nofollow noopener noreferrer" target="_blank"><sup>[36]</sup></a>. It aligns with ISO 10218 Parts 1 and 2, replaces the 2012 edition and folds in the ISO/TS 15066 guidance.

## Technical details

(Skip this unless you're setting up the technical side.)

Three shared ways to move robot data, as of October 2026:

- **OPC UA** is the OPC Foundation's [industrial interoperability standard](https://opcfoundation.org/about/opc-technologies/opc-ua/)<a href="https://opcfoundation.org/about/opc-technologies/opc-ua/" rel="nofollow noopener noreferrer" target="_blank"><sup>[37]</sup></a> for machine data. ABB offers it through its [IoT Gateway](https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway)<a href="https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway" rel="nofollow noopener noreferrer" target="_blank"><sup>[38]</sup></a>, KUKA through [KUKA.DeviceConnector on the KR C5](https://opcfoundation.org/products/view/kr-c5/)<a href="https://opcfoundation.org/products/view/kr-c5/" rel="nofollow noopener noreferrer" target="_blank"><sup>[39]</sup></a> and FANUC as an [OPC UA Server option](https://www.fanucamerica.com/products/software/robot/hmi-device-snpx)<a href="https://www.fanucamerica.com/products/software/robot/hmi-device-snpx" rel="nofollow noopener noreferrer" target="_blank"><sup>[40]</sup></a>. Siemens SIMATIC S7-1200 and S7-1500 controllers [can act as an OPC UA server](https://www.siemens.com/en-us/products/opc-ua/)<a href="https://www.siemens.com/en-us/products/opc-ua/" rel="nofollow noopener noreferrer" target="_blank"><sup>[41]</sup></a>.
- **ROS 2**, the Robot Operating System, is ["a set of software libraries and tools for building robot applications"](https://docs.ros.org/en/lyrical/index.html)<a href="https://docs.ros.org/en/lyrical/index.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[42]</sup></a>. Its documentation says it's [primarily built on top of DDS](https://docs.ros.org/en/lyrical/ROS-Framework/client-libraries/About-Different-Middleware-Vendors.html)<a href="https://docs.ros.org/en/lyrical/ROS-Framework/client-libraries/About-Different-Middleware-Vendors.html" rel="nofollow noopener noreferrer" target="_blank"><sup>[43]</sup></a>, an industry standard for passing data between programs, and now supports other middleware such as Zenoh.
- **MQTT** is a lightweight [OASIS standard messaging protocol](https://mqtt.org/)<a href="https://mqtt.org/" rel="nofollow noopener noreferrer" target="_blank"><sup>[44]</sup></a> for the Internet of Things, now at [version 5](https://mqtt.org/mqtt-specification/)<a href="https://mqtt.org/mqtt-specification/" rel="nofollow noopener noreferrer" target="_blank"><sup>[45]</sup></a>. FANUC sells an [MQTT option](https://www.fanucamerica.com/products/software/robot/mqtt)<a href="https://www.fanucamerica.com/products/software/robot/mqtt" rel="nofollow noopener noreferrer" target="_blank"><sup>[46]</sup></a> for its controllers, and ABB's [IoT Gateway](https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway)<a href="https://www.abb.com/global/en/areas/robotics/products/software/iot-gateway" rel="nofollow noopener noreferrer" target="_blank"><sup>[47]</sup></a> supports it.
