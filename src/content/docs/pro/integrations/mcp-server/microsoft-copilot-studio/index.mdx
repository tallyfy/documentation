## Run your Tallyfy work from Microsoft Copilot

You can run Tallyfy by talking to Microsoft Copilot. Ask it to build a template from your own notes, update tasks after a meeting, or tell you which processes are running late, and it does the work in Tallyfy for you.

You set this up once in Copilot Studio, Microsoft's tool for building your own Copilot agent. After that, you and the people you share it with use the agent in Copilot chat and in Teams.

The ordinary Copilot chat can't add Tallyfy on its own, because it has no place to type in an MCP[^1] server address. That's why setup goes through Copilot Studio.

### What you can do

Some things people ask for:

- Paste a checklist from a Word document and ask for a new template with one step per item.
- Paste your notes from a planning meeting and ask Copilot to add the steps the template is missing.
- Paste a contractor's meeting notes and ask which tasks in the build process they've finished.
- Ask which processes are running late this week, and who's holding them up.
- Ask to move a task from one person to another while someone is away.

### What you need

- **Access to Copilot Studio.** Your IT team decides who can build agents there.
- **A Tallyfy account** in a workspace where AI connections are turned on. If they aren't, Tallyfy's sign-in page tells you so and gives you a ready-made email to ask Tallyfy support to add them.

### Set it up

<Steps>

1. **Create an agent.** Open [Copilot Studio](https://copilotstudio.microsoft.com)<a href="https://copilotstudio.microsoft.com" rel="nofollow noopener noreferrer" target="_blank"><sup>[1]</sup></a> On the home page, select **Other ways to build**, then create a new agent. A name like "Tallyfy assistant" works well.

   **Other ways to build** gives you a standard agent, which is what these steps follow. The cards at the top of the home page build Microsoft's newer GitHub Copilot-based agents instead, which have different menus and different billing (see Microsoft's [Start building guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/authoring-first-bot)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/authoring-first-bot" rel="nofollow noopener noreferrer" target="_blank"><sup>[2]</sup></a> and the Cost section below).

2. **Add Tallyfy as a tool.** On the agent's **Tools** page, select **Add a tool**, then **New tool**, then **Model Context Protocol**.

3. **Fill in the server details.**

   - **Server name**: `Tallyfy`
   - **Server URL**: `https://mcp.tallyfy.com`
   - **Server description**: paste the text below. Copilot reads it to decide when to use Tallyfy, so keep it specific.

   ```text
   Tallyfy runs our business processes. Use it to find, create and edit templates, steps, form fields and automation rules, to launch and track processes, and to read, complete or reassign tasks.
   ```

4. **Choose how to sign in.** Select **OAuth 2.0**[^2], then **Dynamic discovery**, then **Create**, then **Next**. Copilot finds Tallyfy's sign-in details by itself, so there's no key or secret to paste.

5. **Connect your Tallyfy account.** In the **Add tool** box, select **Create a new connection**. A Tallyfy window opens. Sign in, pick your organization if you belong to more than one, and tick the permissions Copilot should have.

   To let Copilot build and edit templates, tick **Create and manage your templates**. Tick **Create and manage form fields** and **Create and manage automation rules** too if you want it to add fields and rules. Then select **Authorize**, and back in Copilot Studio select **Add to agent**.

6. **Keep each person's own sign-in.** In the Tallyfy tool's settings, leave **Authentication** on **End user**. That's Microsoft's default, and it means everyone who uses the agent signs in to Tallyfy as themselves. **Maker-provided** would make every user act as you.

7. **Pick the tools you need.** Tallyfy offers more than 100 tools, and [Microsoft's tools guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-tools-custom-agent)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-tools-custom-agent" rel="nofollow noopener noreferrer" target="_blank"><sup>[3]</sup></a> suggests keeping an agent to 25 to 30 tools for the best results. Every tool starts switched on. Turn off **Allow all**, then turn off each tool you don't need, so you're left with the ones for the job. For building templates, keep the tools in the **Templates and steps** section of [the tool list](/products/pro/integrations/mcp-server/tool-list/), which is about two dozen, and add a few form field tools if you want Copilot to add fields. Once **Allow all** is off, tools Tallyfy adds later start switched off.

8. **Test it.** In the test chat, ask `List my templates in Tallyfy`. You should see your Tallyfy templates.

9. **Put it in Copilot and Teams.** Select **Publish**. Then go to **Channels**, open **Teams and Microsoft Copilot**, make sure **Make agent available in Microsoft Copilot** is selected, and select **Add channel**. Then select **See agent in Teams** and **Add** to install it for yourself.

10. **Share it with colleagues.** Select the three dots (**...**) at the top of the agent, select **Share**, and add people or a security group. Then go back to **Channels** > **Teams and Microsoft Copilot**, select **Availability options**, select **Show to my teammates and shared users**, check that **Show in Built By Your Colleagues** is selected, and select **Update**. They'll find it in the **Built with Power Platform** section of the Teams app store, or you can send them the install link from **Availability options** > **Copy link**. Microsoft's [publishing guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-add-bot-to-microsoft-teams)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/publication-add-bot-to-microsoft-teams" rel="nofollow noopener noreferrer" target="_blank"><sup>[4]</sup></a> has the full details.

</Steps>

### If something goes wrong

- **A Tallyfy page says AI connectors aren't on your plan.** AI connections aren't turned on for your Tallyfy workspace yet. Select **Email support to add it** on that page and Tallyfy support takes it from there.
- **Tallyfy's permission screen says "Unverified third-party application".** You'll see this when you connect Copilot today, because Copilot Studio's sign-in address isn't on Tallyfy's list of known apps yet. Continue only if you started the connection from Copilot Studio a moment ago.
- **Copilot can read but won't change anything.** There are three usual causes. The Tallyfy sign-in it's using may lack the write permission, such as **Create and manage your templates**: remove that Tallyfy connection, sign in again and tick it. The tool it needs may be switched off in the agent's tool list. Or your own Tallyfy role may not allow the change, since Copilot can't do more than you can. If you didn't build the agent, ask the person who did.
- **Signing in or loading the tools fails inside Copilot Studio.** Check Microsoft's [MCP troubleshooting page](https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-troubleshooting)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-troubleshooting" rel="nofollow noopener noreferrer" target="_blank"><sup>[5]</sup></a>, then [contact Tallyfy support](/products/pro/miscellaneous/support/how-can-i-contact-tallyfys-support-team/) with the time it failed and the error you saw.

### Is it secure?

Yes. Two separate sign-ins are involved. You get into Copilot Studio with your normal Microsoft account. Copilot then connects to Tallyfy with a separate **Tallyfy** sign-in. Copilot doesn't pass your Microsoft sign-in to Tallyfy, so you sign in to Tallyfy the way you normally do.

Each person who uses the agent signs in with their own Tallyfy account, so Copilot works inside that person's Tallyfy permissions.

### Keeping it to the people who need it

The agent reaches only the people it's shared with, so you can start with one person and widen it later. A few settings decide who gets what:

- **Data policies.** Copilot Studio reaches the Tallyfy server through a Power Platform connector, so your data policies apply to it, and blocking that connector blocks the Tallyfy tools ([Microsoft's data policy guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-data-loss-prevention)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-data-loss-prevention" rel="nofollow noopener noreferrer" target="_blank"><sup>[6]</sup></a>). If your policy's **Custom connectors** page tags the `*` pattern as Blocked, add a pattern for `https://mcp.tallyfy.com*` above it and tag it Business ([custom connector patterns](https://learn.microsoft.com/en-us/power-platform/admin/dlp-custom-connector-parity)<a href="https://learn.microsoft.com/en-us/power-platform/admin/dlp-custom-connector-parity" rel="nofollow noopener noreferrer" target="_blank"><sup>[7]</sup></a>).
- **Sharing.** The agent's **Share** option gives named people or security groups access ([Microsoft's sharing guide](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-share-bots)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-share-bots" rel="nofollow noopener noreferrer" target="_blank"><sup>[8]</sup></a>). Listing it for the whole company in the Teams app store needs your admin's approval. The same guide lists the licenses and sign-in settings the people you share with need, so check those before you widen access.

### Cost

Microsoft's [billing rates table](https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management)<a href="https://learn.microsoft.com/en-us/microsoft-copilot-studio/requirements-messages-management" rel="nofollow noopener noreferrer" target="_blank"><sup>[9]</sup></a> lists generative answers and agent actions, the features this setup uses, as "No charge" when a person with a Microsoft 365 Copilot license uses the agent under their own identity. People without that license use Copilot Credits, and so do agent flows started by other triggers. Check the conditions on that page for your tenant.

That applies to standard agents, which step 1 creates. Microsoft's newer GitHub Copilot-based agents use consumption-based billing: building, testing and running them can use Copilot Credits that a Microsoft 365 Copilot license doesn't cover, according to Microsoft's [cost guide for those agents](https://learn.microsoft.com/en-us/power-platform/admin/manage-usage-github-copilot-harness)<a href="https://learn.microsoft.com/en-us/power-platform/admin/manage-usage-github-copilot-harness" rel="nofollow noopener noreferrer" target="_blank"><sup>[10]</sup></a>.

To set a hard ceiling, open the Power Platform admin center, go to **Licensing** > **Copilot Studio** > **Manage Agents**, and set a monthly credit limit on the agent. Leave pay-as-you-go unlinked unless you've decided to use it. Microsoft's [credit limits guide](https://learn.microsoft.com/en-us/power-platform/admin/manage-copilot-studio-copilot-credits-capacity)<a href="https://learn.microsoft.com/en-us/power-platform/admin/manage-copilot-studio-copilot-credits-capacity" rel="nofollow noopener noreferrer" target="_blank"><sup>[11]</sup></a> walks through it.

Copilot Cowork is a different product and is billed per use. This setup doesn't need it.

On the Tallyfy side, AI connections have to be on your Tallyfy plan. If they aren't, the sign-in page offers Tallyfy's AI connector add-on and shows its price.

### Data and compliance

Copilot sends Tallyfy what each person asks about, and Tallyfy sends back what that person's account can see. Once data reaches Tallyfy, your agreement with Tallyfy covers it. Microsoft's [agent settings guide](https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-settings)<a href="https://learn.microsoft.com/en-us/microsoft-365/admin/manage/agent-settings" rel="nofollow noopener noreferrer" target="_blank"><sup>[12]</sup></a> says data processed by non-Microsoft services isn't subject to Microsoft agreements. Tallyfy's security and compliance details are on the [compliance page](/products/pro/compliance/).

Tallyfy doesn't block anyone from typing sensitive data into a form field or a comment. If you handle regulated data, decide what belongs in Tallyfy before you widen access.

## For developers

*(Skip this unless you're setting up the technical side.)*

### Server endpoint and support status

The MCP server is hosted at `https://mcp.tallyfy.com` and exposes the full Tallyfy tool set over streamable HTTP. `https://mcp.tallyfy.com/mcp` reaches the same server. It's listed on the [Official MCP Registry](https://registry.modelcontextprotocol.io/?q=tallyfy)<a href="https://registry.modelcontextprotocol.io/?q=tallyfy" rel="nofollow noopener noreferrer" target="_blank"><sup>[13]</sup></a> as `com.tallyfy/mcp-server`. The full list of tools is on [Every tool the MCP server gives your AI](/products/pro/integrations/mcp-server/tool-list/).

Tallyfy also has a [Power Automate connector](https://learn.microsoft.com/en-us/connectors/tallyfy/)<a href="https://learn.microsoft.com/en-us/connectors/tallyfy/" rel="nofollow noopener noreferrer" target="_blank"><sup>[14]</sup></a> listed by Microsoft. The MCP server is added through Copilot Studio's own MCP wizard, so you don't need to build a custom connector or write an OpenAPI file.

### How sign-in works

Copilot Studio's **Dynamic discovery** option reads Tallyfy's discovery documents, registers itself as a client, and runs the authorization code flow. You don't configure any of it by hand.

| Item | Value |
|---|---|
| Protected resource metadata | `https://mcp.tallyfy.com/.well-known/oauth-protected-resource` |
| Authorization server metadata | `https://mcp.tallyfy.com/.well-known/oauth-authorization-server` |
| Client registration | `https://mcp.tallyfy.com/mcp/oauth/register` |
| Authorization | `https://mcp.tallyfy.com/mcp/oauth/authorize` |
| Token | `https://mcp.tallyfy.com/mcp/oauth/token` |
| Grant types | `authorization_code`, `refresh_token` |
| PKCE | `S256`, required |
| Client authentication | `none`, `client_secret_post`, `client_secret_basic` |
| Access token lifetime | 1 hour |
| Refresh token lifetime | 30 days |

The twelve scopes follow `mcp.{resource}.{action}`, with `read` and `write` for each of `users`, `tasks`, `processes`, `templates`, `forms` and `automation`. The person signing in chooses which ones to grant on Tallyfy's consent screen, whatever the client asked for. A normal MCP request with no valid bearer token gets `401` with a `WWW-Authenticate` header that points at the protected resource metadata.

Three tools, `ask_user_question`, `ask_user_to_rank` and `ask_user_to_confirm`, are built for Tallyfy's own chat window, which shows their answer as a form. Turn them off in Copilot.

### Multi-agent orchestration

Copilot Studio can coordinate multiple specialized agents for workflows like employee onboarding.

```d2
direction: down

Start: "User Request\n(New Employee)" {
  shape: circle
  style.fill: "#e1f7e6"
}

Primary: "Primary Agent\n(Orchestrator)" {
  shape: hexagon
  style.fill: "#fff3cd"
}

Analyze: "Analyze\nRequirements" {
  shape: rectangle
  style.fill: "#fff3cd"
}

HR: "HR Agent" {
  shape: rectangle
  style.fill: "#f2faf4"
}

IT: "IT Agent" {
  shape: parallelogram
  style.fill: "#e1f7e6"
}

Training: "Training Agent" {
  shape: document
  style.fill: "#f2faf4"
}

Monitor: "Progress\nMonitor" {
  shape: hexagon
  style.fill: "#fff3cd"
}

Tallyfy: "Tallyfy\nTracker" {
  shape: cylinder
  style.fill: "#e1f7e6"
}

End: "Onboarding\nComplete" {
  shape: circle
  style.fill: "#e1f7e6"
}

Start -> Primary: "Initiate\nonboarding" {
  style.stroke: "#225930"
}

Primary -> Analyze: "Parse request" {
  style.stroke: "#225930"
}

Analyze -> HR: "Create HR\ntasks" {
  style.stroke: "#225930"
}

Analyze -> IT: "Create IT\ntasks" {
  style.stroke: "#225930"
}

Analyze -> Training: "Schedule\ntraining" {
  style.stroke: "#225930"
}

HR -> Monitor: "Report\nprogress" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}

IT -> Monitor: "Report\nprogress" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}

Training -> Monitor: "Report\nprogress" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}

Monitor -> Tallyfy: "Update\nstatus" {
  style.stroke: "#225930"
}

Tallyfy -> End: "Process\ncomplete" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
```

**What to notice:**
- The Primary Agent acts as an orchestrator, delegating to specialized agents
- Each agent creates and manages its tasks through Tallyfy's API
- All progress is monitored through Tallyfy's tracker view

A few worked examples of agents in action:

- **Multi-agent onboarding.** Prompt: *"Start the employee onboarding process for Jane Smith, assign tasks to HR and IT, and schedule training sessions."* The primary agent receives the request, delegates documentation tasks to the HR agent (via Tallyfy), system-access setup to the IT agent, and session scheduling to the Training agent, monitors progress across all of them, and reports a consolidated status back to you.
- **Power Platform integration.** Prompt: *"When a new sales opportunity is created in Dynamics 365, start our proposal process in Tallyfy and create a Teams channel for collaboration."* A Power Automate flow triggers on the Dynamics 365 opportunity, the MCP server creates a Tallyfy process instance, the Teams connector creates a dedicated channel, and the agent monitors and reports progress.
- **Enterprise compliance.** Prompt: *"Review all completed audit processes this quarter and generate a compliance report with any violations highlighted."* The agent queries Tallyfy for audit process data, analyzes completion times against SLAs, checks for required approvals, generates a formatted report in SharePoint, and routes it to the compliance team if violations are found.

More example prompts that work well here:

- *"When a purchase order exceeds $50,000 in Dynamics 365, initiate our approval workflow in Tallyfy, notify team leads in Teams, and track in Power BI."*
- *"Monitor all SOX compliance processes, ensure proper segregation of duties, and generate audit reports with full trail documentation."*
- *"Coordinate our product launch process across marketing, sales, and operations teams, with each department's agent handling their specific tasks."*
- *"Analyze our customer service processes to identify bottlenecks, suggest optimizations, and automatically implement approved changes."*
- *"Manage our FDA submission process with full audit trails, approval chains, and automatic compliance checking at each step."*

Multi-agent setups delegate tasks between specialized agents, keep context across agent handoffs, give you central monitoring of the whole workflow, and include built-in error handling and fallback.

### Power Platform features

- **Power Automate flows** - trigger workflows from MCP actions
- **Power Apps integration** - build custom UIs for Tallyfy data
- **Dataverse storage** - store workflow metadata in Microsoft's database
- **Power BI reporting** - create dashboards from Tallyfy analytics

Copilot Studio also gives you a tools and prompts framework: a **prompt library** to create and share custom prompts across agents, a **tool catalog** to browse and install prebuilt MCP connectors, **version control** to track changes to tools and prompts, and a **testing framework** to validate tools before deployment.

[^1]: Model Context Protocol, the open standard AI assistants use to connect to apps like Tallyfy.
[^2]: OAuth is the standard that lets you allow one app to act in another for you, without giving it your password.
