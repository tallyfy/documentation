## Google Workspace SAML/SSO integration

Connect Google Workspace (formerly G Suite) with Tallyfy using SAML-based Single Sign-On. Your users authenticate with their Google credentials - no separate Tallyfy passwords needed.

:::note[You set this up yourself]
SSO is self-serve. You configure both sides: create the custom SAML app in Google, then paste its metadata into Tallyfy under **Settings > Organization > Security > SSO**. No support ticket needed.
:::

### Requirements

- Google Workspace admin account with super-administrator privileges
- A Tallyfy administrator account on any paid plan
- The Tallyfy SP values from the SSO wizard (shown when you pick Google Workspace)

### Phase 1 - Create a custom SAML app in Google Workspace

#### Step 1: Create a custom SAML application

<Steps>
1. Sign in to the [Google Workspace Admin console](https://admin.google.com/)
2. Go to **Apps** > **Web and mobile apps**
3. Click **Add App** > **Add custom SAML app**

    ![Add custom SAML application](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-add-saml-app.png)
</Steps>

#### Step 2: Configure basic app settings

<Steps>
1. Enter "Tallyfy" as the application name
2. Optionally upload the Tallyfy logo
3. Click **Continue**
</Steps>

#### Step 3: Collect Google identity provider details

<Steps>
1. On the **Google Identity Provider details** page, copy the **SSO URL** (Single Sign-On URL).
2. Copy the **Entity ID** (Issuer).
3. Download the **Certificate** file.

    ![Google Identity Provider Details](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-idp-details.png)
</Steps>

#### Step 4: Configure service provider details

Get the Tallyfy SP values from the wizard first: in Tallyfy, go to **Settings > Organization > Security > SSO**, start a new connection, pick **Google Workspace**, and copy the **SP ACS URL** and **SP Entity ID** it shows. Then, back in Google:

<Steps>
1. Enter the Tallyfy **ACS URL** (Assertion Consumer Service URL) from the wizard.
2. Enter the Tallyfy **Entity ID** (Service Provider Entity ID) from the wizard.
3. Leave the **Start URL** field empty.

    ![Service Provider Configuration](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-service-provider.png)
</Steps>

#### Step 5: Configure attribute mapping

Map these user attributes exactly as shown:

| Google Directory Attribute | App Attribute |
|----------------------------|--------------|
| Primary Email | email |
| First Name | FirstName |
| Last Name | LastName |

Click **Finish**. That's it for the Google side.

#### Step 6: Enable user access

<Steps>
1. In the application settings, go to **User Access**
2. Set **Service status** to **ON for everyone** (or pick specific organizational units)

    ![Enable User Access](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-user-access.png)
</Steps>

### Phase 2 - Enter your Google details in Tallyfy

Back in the Tallyfy SSO wizard (**Settings > Organization > Security > SSO**), move to the **Enter IdP details** step and provide the Google details you collected in Step 3.

<Steps>
1. **XML paste** - if you downloaded Google's IdP metadata, paste the file. Easiest option.
2. **Manual entry** - enter the **SSO URL**, the **Entity ID**, and the **Certificate** instead.

    ![Tallyfy SAML Configuration](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-saml-config.png)
</Steps>

Google Workspace doesn't publish a fetchable per-app metadata URL, so use XML paste or manual entry here.

### Phase 3 - Test and enable in Tallyfy

<Steps>
1. Run the wizard's **Test connection** step and fix anything it flags.
2. Once the test passes, click **Enable** to turn SSO on for your organization.

    ![Enable SAML](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-enable-saml.png)
</Steps>

### User provisioning and access

After you finish the integration:

<Steps>
1. Share your org's SSO login URL with your users (you'll find it in the SSO wizard next to the connection).

    ![Tallyfy Login URL](https://screenshots.tallyfy.com/tallyfy/pro/google-sso-login-url.png)
2. Confirm you've granted access to the SAML app in Google Workspace for users who need it.
3. Existing Tallyfy users sign in through the shared SSO URL - no separate passwords required.
4. New users from a verified domain are provisioned on first login when auto-join is on. Verify your domain under the **Domains** tab first. See [Domain verification](/products/pro/integrations/authentication/domain-verification/).
</Steps>

### How the authentication flow works

Here's the full SAML authentication flow after configuration is done.

```d2
# Google Workspace SSO sign-in flow
direction: down

Open: "1. User opens your\nSSO login URL"
Redirect: "2. Tallyfy sends\nthem to Google"
Login: "3. User signs in\nwith Google"
OK: "Google accepts\nthe login?" {
  shape: diamond
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}
Fail: "Sign-in fails\nat Google"
Back: "4. Google sends a SAML\nresponse to Tallyfy"
Exists: "Account for\nthis email?" {
  shape: diamond
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}
Create: "5. Tallyfy creates\nthe account"
SignIn: "6. Tallyfy signs\nthe user in"

Open -> Redirect -> Login -> OK
OK -> Fail: No
OK -> Back: Yes
Back -> Exists
Exists -> Create: No
Exists -> SignIn: Yes
Create -> SignIn
```

**Key points:**
- **Automatic provisioning** - New users from a verified domain are created on first login (step 5) when auto-join is on. No manual account setup needed.
- **Attribute mapping** - The email, FirstName, and LastName attributes in the SAML response (step 4) control how accounts are created and matched.
- **Single authentication point** - Users only authenticate with Google (step 3), never entering Tallyfy passwords.

### Troubleshooting

Running into authentication problems? Check these:
- Has the user been granted access to the SAML app in Google Workspace?
- Are the attribute mappings correct? Double-check the table above - case matters.
- Is the user accessing Tallyfy through the right SSO URL?
- Still stuck? Contact Tallyfy Support.

### Directory sync with Google Workspace

Google Workspace doesn't push SCIM to custom SAML apps the way Okta, Microsoft Entra ID, and OneLogin do, so there's no SCIM connector to wire up on the Google side here. For Google, the practical pattern is verified-domain auto-join: any Google user on a [verified domain](/products/pro/integrations/authentication/domain-verification/) gets a Tallyfy account on first SSO login. If you want full directory sync (automatic deactivation and group-to-role mapping) and you also run Okta or Entra, configure [SCIM provisioning](/products/pro/integrations/authentication/scim-provisioning/) through that provider instead.
