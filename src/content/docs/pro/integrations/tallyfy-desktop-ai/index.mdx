## What Tallyfy Desktop is

Tallyfy Desktop is a cross-platform Electron app for macOS, Windows, and Linux. v1 of the app was a thin shell around the Tallyfy web client. v2.0.0 adds an AI-first surface, with your Tallyfy workspace as the system of record.

The window has three tabs. **AI Chat** is where you talk to any of four AI assistants. **Web App** is the same Tallyfy web client that v1 showed. **Terminal Jobs** lists every AI run. From any AI chat, you can create a Tallyfy task, launch a process, or edit a template without leaving the chat.

## What v2.0.0 brought in

### 1. Four AI providers

The **Provider** dropdown in the **AI Chat** tab lists each AI assistant Tallyfy Desktop supports:

- **Claude** (Anthropic) - the only provider with tool use, thinking, and browser automation through Chrome
- **Codex** (OpenAI) - text streaming via the official `codex` CLI
- **Gemini** (Google) - streaming chat with MCP support
- **Ollama** (local) - your own models, running entirely on your machine

A provider that isn't installed and signed in shows "(not installed)" after its name, so you can tell which assistant is ready to use.

Connect each one with its own short guide:

### 2. The Task Intent Widget

The Task Intent Widget is the feature that turns chat into Tallyfy work. As the AI replies, the desktop app watches its text for phrases like "create a task for John" or "let's run the onboarding process." When it spots an intent, it shows a widget inline in the chat bubble that creates the task, launches the process, or edits the template in your Tallyfy account.

Read the full [Task Intent Widget guide](/products/pro/integrations/tallyfy-desktop-ai/task-intent-widget/) for details on the widget's states, the per-intent prefill shapes, and how the two-stage detector keeps false positives down.

### 3. Mandatory Tallyfy sign-in

You sign into your Tallyfy account before any tab is visible. The app shows a single "Sign in to Tallyfy" screen on first launch. After sign-in, the app encrypts your session token with your operating system's secure storage (Keychain on macOS, DPAPI on Windows, libsecret on Linux) and saves it on your machine. If your Linux system has no secure storage, the app can't store your session token.

Everything else in the app, from MCP injection to task wrapping to the intent widget, needs your Tallyfy identity. Without it, the AI doesn't know who you are, what org you're in, or where to put the tasks it creates.

### 4. Tallyfy MCP auto-injection

Every Claude and Gemini chat gets the [Tallyfy MCP server](/products/pro/integrations/mcp-server/) added automatically, ahead of any other MCP server. You don't paste a URL into a config file. You don't run `claude mcp add`. The desktop app handles it behind the scenes using your Tallyfy session token.

So Claude and Gemini know about your tasks, processes, templates, members, and guests from the moment you open a chat. Ask Claude "what tasks do I have due this week?" and it answers without any setup.

Codex and Ollama don't support MCP servers in this version, so they can't read or change your Tallyfy data. The Task Intent Widget still works with both.

### 5. A Tallyfy task for every AI run

Every AI run becomes a Tallyfy task. On your first run, the app creates a system checklist titled `__AI_RUNS__` and then adds one task to it per run. The task title shows the provider and the first 100 characters of your prompt. The task also records the model and start time, and when the run ends, its status, duration, and estimated cost (where available). If Tallyfy can't be reached when a run starts, the run still goes ahead without a task.

A successful run completes its task. A failed or cancelled run leaves its task open, and a failed run's task shows the error, so you can see what happened from your Tallyfy account, days or weeks later, on any device. The desktop app stores the raw run events locally; the Tallyfy task is the record you can reach from other devices.

### 6. Local SQLite run history (Terminal Jobs tab)

The Terminal Jobs tab is the desktop app's view of every AI run. It lists runs newest first, with the provider, prompt, status, elapsed time, and cost. Click a row to see the full streamed output of that run. Read the [Terminal Jobs guide](/products/pro/integrations/tallyfy-desktop-ai/terminal-jobs/) for details.

The data is stored in a local SQLite database on your machine. Run events never leave the device. The Tallyfy task is the only record of the run that goes to Tallyfy, and it holds only the details listed above.

### 7. Auto-installer

When the provider you pick isn't installed, an **Install** button appears next to the **Provider** dropdown. Clicking it opens the Install Wizard. The wizard shows exactly what command will run and lists the risks: what it downloads, where it writes files, and any background service it starts. Its **Install** button only works while you hold the Shift key. After install, it runs a check command to confirm the CLI works and shows the version it found.

The install commands are baked into the app source code (not fetched at runtime), so what you consent to is what runs. The exact commands per provider are listed in each provider's connect guide.

## Subscription-only AI

Tallyfy Desktop v2.0.0 does not accept API keys. You connect via your existing AI subscription:

- **Claude** uses OAuth via your Claude.ai account (Pro, Max, Team, or Enterprise plan)
- **Codex** uses OAuth via your ChatGPT account (Plus, Pro, Business, Enterprise, or Edu plan)
- **Gemini** uses OAuth via your Google account
- **Ollama** runs locally on your machine; no account, no subscription

API keys are long-lived secrets that easily leak; OAuth tokens are short-lived and scoped. You sign in through each provider's official CLI, so you keep one billing relationship per provider and your usage counts against that subscription.

## Privacy and data flow

What the desktop app does with your data:

1. Prompts you type go straight to the AI provider you selected, and the app keeps a copy in its local SQLite database.
2. Streamed responses come back from the provider, render in the chat window, and are recorded in the local SQLite database.
3. Run metadata (provider, model, the first 100 characters of the prompt, status, cost, duration) is sent to Tallyfy as a task in the `__AI_RUNS__` checklist.
4. Tallyfy state the AI reads or writes (tasks, processes, templates) goes through the Tallyfy MCP server and is logged in your existing Tallyfy audit trail.

Ollama runs on your machine, so your prompts and its replies never go to an AI company's servers. The Tallyfy task is still created (because the run is still tracked), and its title carries the first 100 characters of your prompt.

## First launch: OS security prompts (v2.0.0)

v2.0.0 is not yet code-signed, so your operating system warns you the first time you open it.

### macOS

Double-clicking the app the first time shows: "Tallyfy cannot be opened because Apple cannot check it for malicious software." Click Cancel, then **right-click (or Control-click) the Tallyfy app and choose Open** from the menu. macOS shows a second prompt with an Open button. Click Open. After this one-time approval, you can launch normally. Apple Silicon Macs are stricter than Intel and always need this right-click path on first launch.

### Windows

Running the installer the first time shows: "Windows protected your PC. Microsoft Defender SmartScreen prevented an unrecognized app from starting." Click **More info** (the small link), then **Run anyway**. SmartScreen eases up after the binary builds reputation across enough machines.

### Linux

`.AppImage` and `.deb` install without OS security prompts. If the AppImage will not run, mark it executable: `chmod +x Tallyfy-2.0.0.AppImage`.

Signed releases (which install without these warnings) land in a future v2.0.x once we provision the certificate.
