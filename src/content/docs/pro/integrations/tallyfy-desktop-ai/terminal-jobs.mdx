## What the Terminal Jobs tab is

The Terminal Jobs tab is the Tallyfy Desktop list of the AI runs you've started. Each row is one run: provider, prompt, status, elapsed time, and cost (where the provider reports it). Click any row to open a panel with every event that run streamed.

![Terminal Jobs tab with several entries showing provider, model, duration, and status](https://screenshots.tallyfy.com/desktop-ai/terminal-jobs.png)

## Every run is also a Tallyfy task

In v2.0.0, every AI run, including local Ollama runs, also creates a task in a system Tallyfy checklist titled `__AI_RUNS__`. Tallyfy Desktop creates the checklist on your first run. The task records:

- The provider (Claude, Codex, Gemini, Ollama) and the first 100 characters of your prompt, in the title, such as `AI run (claude): Summarize this contract`
- The model name, when it's known
- The start time
- When the run ends: its status, the estimated cost (where available), the duration, and the error message if it failed

A successful run completes its task. A failed or cancelled run leaves its task open, with the error message if there was one, so you can see what happened from any device that has access to your Tallyfy account. If Tallyfy can't be reached when a run starts, the run still goes ahead without a task.

This is how Terminal Jobs and Tallyfy work in tandem:

| View | Lives on | Best for |
|---|---|---|
| Terminal Jobs tab | Your local SQLite database | Live view of running jobs, every streamed event, cancellation |
| `__AI_RUNS__` checklist in Tallyfy | Tallyfy cloud | Run history across devices, audit trail |

If you have Tallyfy Desktop installed on two computers, each one has its own Terminal Jobs tab (showing only that machine's runs), but the `__AI_RUNS__` checklist in Tallyfy shows every run from every machine.

## Reading a run row

Each row shows:

- **Provider** - an icon and the provider name (claude, codex, gemini, or ollama)
- **Prompt** - the first 80 characters of your prompt. Hover over it to see the whole prompt.
- **Status** - one of:
  - **running** - active right now
  - **completed** - finished without error
  - **error** - hit an error; expand the row to see it
  - **cancelled** - you cancelled it before it finished
- **Elapsed** - how long the run took, in minutes and seconds (or hours, minutes, and seconds). It counts up every second while the run is going.
- **Cost** - the cost in US dollars that the provider reported, or a dash when there's none. Claude reports cost, Ollama always shows $0.0000, and Codex and Gemini show a dash.

The run id and the model appear at the top of the panel when you expand the row.

## Viewing run details

Click a row, or select it and press Enter or Space, to expand it. Only one row is open at a time. The panel shows:

1. **The run id and model** at the top
2. **Every event the run streamed**, numbered in order, with its type and contents: the assistant's text (and its thinking, for Claude), tool calls and their results, errors, and the final result with token usage where the provider reports it
3. **The error** at the bottom, if the run failed

The panel is read-only, and it keeps updating while the run is still going. To see a run from your current session as a chat again, pick it in the run history list on the left of the **AI Chat** tab.

## Cancelling a running job

To stop runs from this tab, click **Cancel all running** in the toolbar. It cancels every running job in the list as it's currently filtered. To stop only the run you're watching in the **AI Chat** tab, click **Cancel** under the chat.

For Claude, Codex, and Gemini, Tallyfy Desktop uses a tiered cancellation policy:

1. **SIGINT** - sent first. The CLI gets a clean interrupt; most providers stop within a second or two.
2. **SIGTERM** - sent after 2 seconds if SIGINT didn't take. Forces a process termination.
3. **SIGKILL** - sent after another 5 seconds if SIGTERM didn't take. Unconditional kill.

The cancelled run emits a clean `error` event with code `cancelled`, and its status becomes **cancelled**. Partial output up to the cancel point stays in the run's events. Its Tallyfy task stays open.

For Ollama runs (which talk to the local daemon over HTTP), cancellation aborts the HTTP request through an `AbortSignal`, and the daemon stops generating tokens.

## Filtering the list

The toolbar has three filters, and they combine:

- **Provider** - All providers, Claude, Codex, Gemini, or Ollama
- **Status** - All statuses, Running, Success, Error, or Cancelled
- **Time range** - Last 24h (the default), Last 7 days, Last 30 days, or All time

Runs older than 24 hours stay hidden until you change **Time range**. The tab loads the 500 most recent runs.

**Clear completed** hides every run that isn't running. It doesn't delete anything, and **Show completed** brings them back.

## Local SQLite storage

The Terminal Jobs data lives in a SQLite database on your machine at:

- **macOS**: `~/Library/Application Support/Tallyfy/runs.db`
- **Windows**: `%APPDATA%\Tallyfy\runs.db`
- **Linux**: `~/.config/Tallyfy/runs.db`

Why local: AI runs can contain sensitive prompts (HR conversations, contract drafts, code with API keys you accidentally pasted). Storing the raw event stream locally means the only cloud copy is the Tallyfy task, which is much narrower.

The database has two tables:

- `runs` - one row per run: provider, model, the full prompt, start and end times, status, cost, the Tallyfy task id, and any error
- `events` - every streamed event for each run (text chunks, tool calls, errors, and the final result)

Tallyfy Desktop doesn't prune old runs or events, so the `events` table grows with long chats.

## Privacy guardrails

A few things Terminal Jobs does *not* do:

- It doesn't send the raw streamed events to Tallyfy. Only the task details listed above go to Tallyfy.
- It doesn't send run content anywhere else. Tallyfy Desktop's telemetry stays off until you agree to it, and even then it records only each run's provider, model, status, duration, cost, and error code, never prompt or reply text.
- It doesn't store your Tallyfy session token in `runs.db`. The token is kept in your operating system's secure storage, and `runs.db` has no field for it.

## What this enables

Because every AI run is a Tallyfy task, you can check on your runs from any device where you can open Tallyfy. Failed and cancelled runs stay open as tasks in the `__AI_RUNS__` checklist.

The [Task Intent Widget](/products/pro/integrations/tallyfy-desktop-ai/task-intent-widget/) is the inbound side of this loop. Terminal Jobs is the outbound side: it's the audit trail of every run that happened.
