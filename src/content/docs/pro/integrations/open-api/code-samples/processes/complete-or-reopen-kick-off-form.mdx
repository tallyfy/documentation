## Changing kick-off answers on a running process

To change a kick-off answer and have automations follow it, do three calls in order: re-open the
form, save the new values, then complete it. Saving values on their own updates what the process
shows, and it doesn't re-apply any automation.

Replace `{org_id}` and `{run_id}` with your IDs. The two `complete-prerun` calls don't take a
request body.

- `Authorization: Bearer {your_access_token}`
- `Accept: application/json`
- `X-Tallyfy-Client: APIClient`

## Re-open the kick-off form

`DELETE /organizations/{org_id}/runs/{run_id}/complete-prerun`

This clears `prerun_completed_at` and `prerun_completed_by` and sets the process `status` to
`active`, so a completed process becomes active again. It returns the process. It doesn't touch
any automation.

## Save the new values

`PUT /organizations/{org_id}/runs/{run_id}` with a `prerun` object. Keys are the kick-off field
timeline IDs. See [update process](/products/pro/integrations/open-api/code-samples/processes/update-process/).

## Complete the kick-off form

`POST /organizations/{org_id}/runs/{run_id}/complete-prerun`

This sets `prerun_completed_at` and checks every automation with at least one condition on a
kick-off field:

- An automation that has never run in this process runs all its actions if it matches now.
- For an automation that already ran, deadline and visibility actions are worked out again if a condition's result has changed, or the date a deadline counts from has moved. If neither changed, nothing moves. Its status (reopen), assignment and webhook actions never run a second time in the process.
- A show or hide that still holds isn't applied again, including one that found the task already that way, so a change someone made by hand since stands. An automation with a "step is reopened" condition is the exception: it keeps no record, so it applies its show or hide again on each re-check while it holds.
- A show or hide that no longer holds is reversed, except on a task whose work has started (in progress or completed, a saved form value, or an assignee or guest who has finished their part). It's also kept while another automation that still holds applies the same show or hide; that automation takes it over and reverses it when it stops holding. One that changed nothing is dropped without touching the task, and one from an automation with a "step is reopened" condition is never reversed.
- Every completion of the form after launch is a repeat, so no hide touches a task whose work has started, even from an automation that matches for the first time. Only launch hides in-progress tasks.
- A deadline doesn't move when the task is completed, when it carries `deadline_set_by_hand: true`, or when the action has nothing to count from. Nor does it when the action counts from its target task's own date, or from a task whose date counts from it. A deadline that works out to the date it already has isn't reported as a change.
- A deadline an automation moves also moves the tasks whose deadlines count from it. No comment or notification goes out in the caller's name, and watchers aren't emailed. The moved task gets a comment that names nobody, saying its deadline moved on its own and that nobody edited it. Each following task whose date moved gets one too, saying which task it follows. Neither is posted at launch. The "moved on its own" comment goes by whether the task was visible when this check started: a task hidden then gets none, even if the same automation shows it, and a task visible then still gets it, even if the check hides it. A task that's hidden when the date it follows moves gets no follow comment.
- The first time an automation shows a task in this process, the task's assignees get the "It's your turn" email. A show applied again sends none, and neither does a task that comes back because a hide was reversed.
- On a process that was already running when re-applying shipped, the first re-check of each automation that ran before records where the answers stand and moves nothing. Later changes re-apply.

A kick-off date field that doesn't collect a time counts from 17:00 on that date, in the
organization's timezone.

Calling `POST` on a form that's already complete returns straight away without checking any
automation. Re-open it first.

The response is the process. It includes `tasks_changed_by_rules`, keyed by task ID, listing the
tasks automations changed on this call, each with its `triggered_actions` types, such as
`deadline`, `visibility`, `assignment` or `status`. That includes the assignment and reopen targets
of an automation running for the first time. A
task whose show or hide was reversed is listed. A deadline worked out to the date it already had
isn't, and neither are tasks that only followed a moved date through the step chain.

:::note[New field: `rules_evaluated`]
The release that re-applies automations adds `rules_evaluated` (boolean) to this response. It's
`true` when Tallyfy checked the automations. It's `false` when the form was already complete, or
when the organization's plan doesn't run automations, so nothing was checked. Before it, an empty
`tasks_changed_by_rules` couldn't tell those cases apart.
:::

Example response, trimmed to the fields this page covers:

```json
{
  "data": {
    "id": "PROCESS_RUN_ID",
    "name": "New hire onboarding - Jane Doe",
    "status": "active",
    "prerun_status": "complete",
    "prerun_completed_at": "2026-10-01T15:04:05Z",
    "prerun_completed_by": 1001,
    "rules_evaluated": true,
    "tasks_changed_by_rules": {
      "TASK_ID": {
        "id": "TASK_ID",
        "title": "Launch manager onboarding",
        "status": "not-started",
        "triggered_actions": ["deadline"]
      }
    }
  }
}
```

## Code samples

<Tabs>
<TabItem label="JavaScript">
```javascript
const accessToken = 'YOUR_PERSONAL_ACCESS_TOKEN';
const orgId = 'YOUR_ORGANIZATION_ID';
const runId = 'PROCESS_RUN_ID';
const base = `https://go.tallyfy.com/api/organizations/${orgId}/runs/${runId}`;

const headers = {
  'Authorization': `Bearer ${accessToken}`,
  'Accept': 'application/json',
  'X-Tallyfy-Client': 'APIClient',
  'Content-Type': 'application/json'
};

async function call(method, url, body) {
  const response = await fetch(url, {
    method,
    headers,
    body: body ? JSON.stringify(body) : undefined
  });
  const data = await response.json();
  if (!response.ok) {
    throw new Error(`${method} ${url} failed with ${response.status}: ${JSON.stringify(data)}`);
  }
  return data;
}

async function changeKickoffAnswer() {
  // 1. Re-open the kick-off form
  await call('DELETE', `${base}/complete-prerun`);

  // 2. Save the new value (key is the kick-off field's timeline ID)
  await call('PUT', base, {
    prerun: { 'KICKOFF_FIELD_TIMELINE_ID': '2026-11-02T12:00:00Z' }
  });

  // 3. Complete it, which re-checks automations with kick-off conditions
  const result = await call('POST', `${base}/complete-prerun`);
  console.log('Tasks changed:', Object.keys(result.data.tasks_changed_by_rules || {}));
}

changeKickoffAnswer().catch(error => console.error(error.message));
```
</TabItem>
<TabItem label="Python">
```python
import os
import requests

access_token = os.environ.get('TALLYFY_ACCESS_TOKEN', 'YOUR_PERSONAL_ACCESS_TOKEN')
org_id = os.environ.get('TALLYFY_ORG_ID', 'YOUR_ORGANIZATION_ID')
run_id = 'PROCESS_RUN_ID'
base = f'https://go.tallyfy.com/api/organizations/{org_id}/runs/{run_id}'

headers = {
    'Authorization': f'Bearer {access_token}',
    'Accept': 'application/json',
    'X-Tallyfy-Client': 'APIClient',
}

# 1. Re-open the kick-off form
response = requests.delete(f'{base}/complete-prerun', headers=headers)
response.raise_for_status()

# 2. Save the new value (key is the kick-off field's timeline ID)
response = requests.put(base, headers=headers, json={
    'prerun': {'KICKOFF_FIELD_TIMELINE_ID': '2026-11-02T12:00:00Z'}
})
response.raise_for_status()

# 3. Complete it, which re-checks automations with kick-off conditions
response = requests.post(f'{base}/complete-prerun', headers=headers)
response.raise_for_status()
changed = response.json()['data'].get('tasks_changed_by_rules') or {}
print('Tasks changed:', list(changed.keys()))
```
