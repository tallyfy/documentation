Multi-level approval loops reopen earlier steps automatically when someone rejects. Rejections bounce work back for corrections.

:::caution[Each rejection automation works once per process, so "loop" means one lap]
An automation runs at most once in a given process. Each of the automations below is separate, so
a first rejection by the manager, a first rejection by finance and a first rejection by the COO
all work exactly as described.

A **second** rejection at the same level, later in the same process, does nothing. The automation
that would have reopened the earlier step has already fired, so Tallyfy skips it and the process
carries on as if nobody objected. Nothing on screen says so.

Build for one lap. If your approvals genuinely bounce back repeatedly, reopen the step by hand
after the first round, or split the chain across processes. See [when an automation
runs](/products/pro/documenting/templates/automations/when-automations-run/).
:::

## When to use this

Any workflow needing sequential sign-offs:

- **Financial approvals** - Purchase requests through manager, finance, then executive
- **Content publishing** - Draft, editor review, legal review, final sign-off
- **Contract management** - Department head, legal, CFO, CEO
- **Quality control** - Inspection, supervisor check, quality manager sign-off

Rejection at any level bounces work back to whoever needs to fix it.

## Creating the workflow

Here's how the approval chain flows:

```d2
# Multi-Level Approval Workflow
direction: down

Create: "Create request" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}

Manager: "Manager review" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Finance: "Finance approval" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

COO: "COO approval" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Complete: "Complete" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}

Create -> Manager: "Submit" {
  style.stroke: "#225930"
}
Manager -> Finance: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
Finance -> COO: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
COO -> Complete: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}

# Rejections point back up. Written as <- so the layout keeps the request at the top.
Create <- Manager: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Create <- Finance: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Create <- COO: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Manager <- COO: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
```

**Key points:**
- The first rejection at each level re-opens the creation task
- Later approvals won't appear until earlier ones pass, which [visibility actions](/products/pro/documenting/templates/automations/actions/visibility-actions/)[^1] control
- COO rejection can re-open multiple steps at once

<Steps>
1. **Set up your approval chain steps**

   In your [template](/products/pro/documenting/templates/), make the approval steps **Decision** steps:
   - Step 1: "Create wire transfer request" (regular task)
   - Step 2: "Manager review" (Decision)
   - Step 3: "Finance department approval" (Decision)
   - Step 4: "COO final approval" (Decision)

2. **Create re-open automations for each approval level**

   For each approval step, create an automation using a [status action[^2]](/products/pro/documenting/templates/automations/actions/status-actions/) that fires on rejection:
   
   **Automation 1: a manager rejection reopens the request**
   ```automation
   AUTOMATION Manager rejection reopens the request
   IF step "Manager review" is rejected
   THEN reopen "Create wire transfer request"
   ```
   
   **Automation 2: a finance rejection reopens the request**
   ```automation
   AUTOMATION Finance rejection reopens the request
   IF step "Finance department approval" is rejected
   THEN reopen "Create wire transfer request"
   ```
   
   **Automation 3: a COO rejection can reopen more than one step**
   ```automation
   AUTOMATION COO rejection reopens both earlier steps
   IF step "COO final approval" is rejected
   THEN reopen "Create wire transfer request"
   AND reopen "Manager review"
   ```

3. **Add visibility automations to control the flow**

   Hide later approvals until the earlier ones pass:
   ```automation
   AUTOMATION Reveal finance after the manager approves
   IF step "Manager review" is approved
   THEN show "Finance department approval"
   ```
   ```automation
   AUTOMATION Reveal the COO after finance approves
   IF step "Finance department approval" is approved
   THEN show "COO final approval"
   ```
</Steps>

## Advanced approval patterns

### Conditional approval routing

Route approvals based on field values like amount thresholds, then use a [visibility action](/products/pro/documenting/templates/automations/actions/visibility-actions/) to reveal the next step:

```automation
IF field "Purchase Amount" is greater than "$50,000"
AND step "Manager review" is approved
THEN show "Board approval required"
```

### Parallel approvals

When multiple teams need to review at the same time, use parallel approvals:

```d2
# Parallel Approval Workflow
direction: down

Initial: "Initial review" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}

Legal: "Legal\napproval" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Compliance: "Compliance\napproval" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Finance: "Finance\napproval" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Check: "All three\napproved?" {
  shape: diamond
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}

Final: "Final step\nappears" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}

Hidden: "Final step\nstays hidden" {
  style.fill: "#fff3cd"
  style.stroke: "#225930"
}

Initial -> Legal: {
  style.stroke: "#225930"
}
Initial -> Compliance: {
  style.stroke: "#225930"
}
Initial -> Finance: {
  style.stroke: "#225930"
}
Legal -> Check: {
  style.stroke: "#225930"
}
Compliance -> Check: {
  style.stroke: "#225930"
}
Finance -> Check: {
  style.stroke: "#225930"
}
Check -> Final: "Yes" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
Check -> Hidden: "No" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
```

**Key points:**
- All three approvals trigger at once after initial review
- The final step waits until ALL parallel approvals complete
- A rejection here re-opens nothing by itself. Add a rejection automation like the ones above if it should send work back

Set this up with [visibility actions](/products/pro/documenting/templates/automations/actions/visibility-actions/):

```automation
IF step "Initial review" is completed
THEN show "Legal approval"
AND show "Compliance approval"
AND show "Finance approval"
```

Then gate the final step on all three approvals:
```automation
IF step "Legal approval" is approved
AND step "Compliance approval" is approved
AND step "Finance approval" is approved
THEN show "Final implementation"
```

### Escalation paths

If approvals get stuck:

1. Set a deadline on the approval step
2. Create an escalation step assigned to senior management
3. Add a step that finishes itself, dated a little after the approval deadline, then trigger the escalation when that step expires. Deadline automations cannot start anything, they only change a deadline, so that step is what acts as the clock

## Best practices

- **Rejection reasons** - Add comment fields so reviewers explain what needs fixing
- **Notifications** - Turn on email notifications so people know when tasks bounce back
- **Plan for one automatic lap** - the automatic bounce-back happens on the first rejection at each level. After that, reopen by hand, and treat a second rejection as the moment to pick up the phone instead
- **Step instructions** - Tell reviewers the exact criteria you're looking for
- **Audit trail** - Tallyfy tracks every approval and rejection automatically

:::note[Re-open behavior]
When Tallyfy re-opens a task:
- Status changes from "Completed" back to "In progress"
- Original assignees get notified
- All previously entered data stays intact
- The task reappears in each assignee's task list

The automation that did the re-opening is spent at that point and won't fire again in this process.
:::

## Example: property listing approval

Here's how a real estate agency handles listing approvals:

```d2
# Property Listing Approval Workflow
direction: down

Agent: "Create listing" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}
Manager: "Manager review" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}
Marketing: "Marketing" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}
Compliance: "Compliance" {
  style.fill: "#f2faf4"
  style.stroke: "#225930"
}
Publish: "Publish" {
  style.fill: "#e1f7e6"
  style.stroke: "#225930"
}

# Approvals move forward
Agent -> Manager: {
  style.stroke: "#225930"
}
Manager -> Marketing: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
Marketing -> Compliance: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}
Compliance -> Publish: "Approved" {
  style.stroke: "#225930"
  style.stroke-width: 2
}

# Rejections return to the agent, and compliance also reopens the manager review
Agent <- Manager: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Agent <- Marketing: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Agent <- Compliance: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
Manager <- Compliance: "Rejected" {
  style.stroke: "#225930"
  style.stroke-dash: 3
}
```

**How it works:**
- Marketing rejection gives the agent specific feedback on photos
- Compliance issues notify both agent and manager
- Agents know exactly what to fix
