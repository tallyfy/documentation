## Automations are checked on completion, never on save

Tallyfy checks automations at set moments: when the process launches, when a task is completed
or reopened, and when the kick-off form is completed again. Typing in a form field and saving it
never starts an automation by itself.

What happens next depends on the kind of action.

- **Deadline and show/hide actions follow your answers.** Each time Tallyfy checks the automation, it works these out again if an answer the automation reads has changed, or the date a deadline counts from has moved. If nothing changed, nothing moves.
- **Reopen, assignment and webhook actions run at most once per process.** Once one of these has fired, it won't fire again in that process. Nobody gets the same assignment twice, and an outside system doesn't get the same webhook twice.

An automation can mix both kinds. Its deadline and show/hide actions can run again, and its
other actions still run only once.

Launch the same template again and you get a fresh process, where every automation starts from
scratch.

## The moments Tallyfy checks

**When the process launches.** Tallyfy looks at every automation with at least one condition on
a kick-off form field, because the kick-off answers are the only answers that exist yet.

**When a task is completed or reopened.** Tallyfy looks at the automations whose conditions
involve that task or the form fields on it. This is why an automation reading a step's form field
doesn't fire the moment somebody types in the field. It fires when the task carrying that field
is completed.

**When the kick-off form is completed again.** Re-open the kick-off form on a running process,
change an answer, and click **Complete**. Tallyfy checks every automation with a kick-off
condition again at that moment. Re-opening the form on its own checks nothing. The steps are in
[changing kick-off answers after launch](/products/pro/launching/triggers/kick-off-forms/).

## When a date or an answer changes mid-process

Here's what happens when a date moves after its automation has run:

1. You enter a start date of 5 September and complete the task.
2. The automation fires and sets a dependent task's deadline to 6 September.
3. You reopen the task, change the start date to 15 September, and complete it again.
4. Tallyfy checks the automation again, sees the start date has moved, and moves the dependent task to 16 September.

Saving the new date without completing the task moves nothing. The check happens on completion.

Show and hide work the same way. Say a kick-off answer of "No" hid five steps at launch. Someone
re-opens the kick-off form, changes the answer to "Yes" and completes it. The rule that hid those
steps no longer holds, so Tallyfy shows them again. It works in the other direction too: a step
a rule showed is hidden again once that rule stops holding.

## What a re-check leaves alone

When Tallyfy checks an automation again after an answer changes, it leaves these alone.

- **Work that's under way.** On a re-check, Tallyfy never hides a step whose work has started, whether it's undoing a Show or applying a Hide that now matches. That means a step that's completed or in progress, has a saved form answer, or has an assignee who's already finished their part. The process's activity feed notes each step it kept. If that step isn't needed any more, [hide it by hand](/products/pro/tracking-and-tasks/tasks/manually-show-hide-tasks/). The first time an automation runs, at launch or on a first completion, a Hide action still hides any step that isn't completed.
- **Steps someone hid or showed by hand.** A re-check doesn't undo a show or hide a person made on the running process.
- **Deadlines someone set by hand.** Once a person picks a date on a task, automations never move it. See [set an exact date on a task](/products/pro/tracking-and-tasks/tasks/edit-task/change-a-task-due-date/).
- **A deadline with nothing to count from.** A deadline action that shifts a step's own due date, like "3 days later than its current deadline", applies once only. Applying it again would add another 3 days every time.
- **A deadline whose rule stops holding.** Only show and hide are reversed. A deadline stays where the automation last put it.
- **Rules that check whether a step was reopened.** What they show stays shown after the reopened step is completed again.

## A deadline an automation moves pushes the steps behind it

A step whose deadline counts from another step follows it. When an automation moves the other
step's deadline, every unfinished step counting from it is worked out again. That's the same thing
that happens when someone completes that step or edits its date by hand.

The one exception is a step whose own date somebody set by hand. It keeps that date, and the
steps behind it count from it.

## Other reasons an automation does nothing

Running isn't the same as having an effect. An automation can fire and still change nothing.

- **The target task is already completed.** Deadline, visibility and assignment actions all skip a task that's finished. There's nothing to shift or hide.
- **A condition reads a field that's still empty.** An empty field is a real value to Tallyfy and it gets compared like any other. A deadline action pointed at an empty date field does nothing, and the task keeps the deadline it already had.
- **The organization's plan doesn't run automations.** Automations run on Pro, Enterprise and AppSumo plans, and during a free trial. A Docs plan doesn't run them, and neither does an organization whose trial has ended without a paid plan. They're still saved on the template, and they start working as soon as the organization is on a plan that runs them.

## Order within one process

Several automations can fire from the same task completion. One automation can also carry several
actions. Where two of them touch the same step, the result depends on which one Tallyfy gets to
last, and that isn't something you should design around.

If a step's deadline has to follow another step's deadline, set that up in the step's
[Timings row](/products/pro/documenting/templates/edit-templates/step-timings/) rather than with
two automations that race each other.
