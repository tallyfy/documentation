## Visibility actions explained

Visibility actions let you **Show** or **Hide** specific steps based on conditions.

Visibility is one of five action types you can add to an [automation](/products/pro/documenting/templates/automations/). The others change [deadlines](/products/pro/documenting/templates/automations/actions/deadline-actions/), [reopen steps](/products/pro/documenting/templates/automations/actions/status-actions/), and update [assignments](/products/pro/documenting/templates/automations/actions/asignment-actions/).

### Examples

**Example 1 - CFO approval for big purchases:**
```automation
AUTOMATION CFO approval for big purchases
IF field "Purchase Amount" is greater than "$10,000"
THEN show "Approval by CFO"
```
The CFO approval step appears automatically for purchases over $10k.

**Example 2 - Skip irrelevant reviews:**
```automation
AUTOMATION Skip irrelevant reviews
IF field "Customer Type" is "Small Business"
THEN hide "Enterprise Security Review"
```
Small business customers skip the enterprise security review entirely.

**Example 3 - Adapt to user input:**
```automation
AUTOMATION Adapt to user input
IF field "Application Type" is "Mortgage"
THEN show "Credit Check"
AND show "Property Valuation"
AND show "Underwriting"
```
Selecting "Mortgage" reveals all mortgage-specific steps at once.

Completing one step makes the next one appear.

:::note[How visibility works]
- Steps are **visible by default**, except a step that a **Show** action targets. Tallyfy hides that step when the process launches, and the automation editor says so under the action.
- There's no setting that hides a step on its own. To hide one from the start of a [template](/products/pro/documenting/templates/), make it the target of a **Show** action.
- A **Hide** action makes steps disappear based on conditions.
- A **Show** action reveals hidden steps when conditions are met.
- Tallyfy checks the automations again when a step they read is completed or reopened, or the kick-off form is completed after launch. A step an automation showed is then hidden again if that automation no longer matches, and a step an automation hid comes back.
- Undoing a **Show** never hides a step once work on it has started. A **Hide** doesn't either, except at launch and on a step's very first completion, where it hides any step that isn't completed. That's true even for an automation that matches for the first time later on.
- While an automation still matches, Tallyfy doesn't apply its **Show** or **Hide** again. So if someone hid or showed that step by hand since, their change stays.
:::

:::warning[Hidden steps can't be completed]
Hidden steps have an internal status of `auto-skipped` and can't be completed. Any automation checking "if step is complete" on a hidden step won't trigger - unless another automation makes that step visible first.

Only create completion-based automations for steps users can actually see. You can also [manually show or hide steps](/products/pro/tracking-and-tasks/tasks/manually-show-hide-tasks/) using the three-dot menu on any task.
:::

:::note[Default behavior: parallel execution]
Procedure templates in Tallyfy show all steps at once by default. People can work on them in any order[^1]. To enforce sequential order, hide steps initially and use **Show** automations to reveal them as earlier steps finish.
:::

### Hiding tasks by default in a template

All tasks show up when someone launches a [procedure template](/products/pro/documenting/templates/). To keep certain tasks hidden until the right moment:

<Steps>
1.  Open your procedure template in the editor.
2.  Create an automation whose **Show** action targets the step you want hidden at first.
3.  Set the automation's conditions to the moment the step should appear.
4.  Save the automation. Tallyfy now hides the step when each process launches.
</Steps>

Hidden steps stay out of sight until a **Show** automation brings them back, or someone shows them by hand.

### Enforcing sequential task order

Sometimes Task B shouldn't start until Task A is done. You can force tasks to appear in sequence using hidden tasks and **Show** visibility actions in your [automations](/products/pro/documenting/templates/automations/)[^2].

<Steps>
1.  **Task A**: Leave it visible by default.
2.  **Task B**: Nothing to set. It starts [hidden](#hiding-tasks-by-default-in-a-template) because automation 1 shows it.
3.  **Task C**: Nothing to set. It starts [hidden](#hiding-tasks-by-default-in-a-template) because automation 2 shows it.
4.  **Create automation 1 (show Task B)**:
    *   **IF** `(Step Status)` for `Task A` **is** `Completed`
    *   **THEN** `(Visibility)` **SHOW** `Task B`
5.  **Create automation 2 (show Task C)**:
    *   **IF** `(Step Status)` for `Task B` **is** `Completed`
    *   **THEN** `(Visibility)` **SHOW** `Task C`
</Steps>

The result:
- Process starts - only Task A shows up
- Complete Task A - Task B appears
- Complete Task B - Task C appears
- Reopen Task A before anyone starts Task B - Task B is hidden again until Task A is completed

You can chain as many tasks as you need this way.
