## Which form field should you use?

Pick the field by the kind of answer you need. The table below matches common needs to a field type.

### Quick decision guide

| What you need | Best field type | Why |
|---------------|-----------------|-----|
| Pick ONE from 2-5 options | **Radio buttons** | All options visible at once |
| Pick ONE from 6+ options | **Dropdown** | Saves space, searchable |
| Confirm multiple items done | **Checklist** | Multi-select with validation |
| Confirm one thing before the task is completed | **Checklist with one item** | The task can't be completed until it's ticked |
| A yes/no question that changes what happens next | **Radio buttons** | Both answers visible, and an automation can act on either |
| A specific date | **Date** | Calendar picker prevents format errors |
| A detailed explanation | **Long text** | Room for multi-line responses |
| Brief data (name, number) | **Short text** | Single line, optional validation |
| Upload evidence/files | **File upload** | Multiple files, up to 100MB each |
| Select a person | **Assignee picker** | Pulls from Tallyfy members, groups, and guests |
| Structured data rows | **Table** | Defined columns, unlimited rows |

### When to use a checklist with one item

A checklist can have just one item. Use it when someone must confirm something before they can complete the task, such as "I accept the policy" or "I handed in the receipt".

To set it up, add a checklist field with a single item. Then choose **At least one item must be checked** as its validation. That makes the field required, so the task can't be completed until the box is ticked.

Radio buttons can't do this. A required Yes/No radio field still accepts "No", so someone can pick "No" and complete the task anyway.

### When Yes/No radio buttons are the better choice

Use Yes/No radio buttons when "No" is a real answer that should change what happens next. Add an [automation](/products/pro/documenting/templates/automations/actions/visibility-actions/) that shows a follow-up step for each answer. Automations show or hide whole steps, not single fields.

**Example - payment confirmation:**

1. **Radio buttons**: "Has payment been received?" - Yes / No
2. **If No**: an automation shows a "Chase the payment" step.
3. **If Yes**: an automation shows a "Record the payment" step. It asks for the date the payment reached the bank, plus an optional file upload for proof, such as a bank statement.

### When to use checklists

Use a checklist with several items when:

- Confirming several related items were completed
- Order of completion doesn't matter
- Some or all items may apply

**Good examples:**

- **Quality check**: "Checked for errors", "Reviewed by a second person"
- **Equipment handover**: "Laptop returned", "Badge collected", "Keys returned"
- **Approval criteria**: "Budget approved", "Legal reviewed", "Manager signed off", "IT security cleared"

**Validation options:**

- **No validation** - nothing has to be ticked.
- **At least one item must be checked** - the field is required, and one tick is enough.
- **All items must be checked** - every item has to be ticked.

### Radio buttons vs dropdown

Both let you pick ONE option. The difference is display.

**Radio buttons** - best for 2-5 options where you want all choices visible at once. Radio fields require at least 2 options.

**Dropdown** - best for 6+ options, or when screen space is tight and options are self-explanatory.

For yes/no questions, always use radio buttons. A two-item dropdown just adds an unnecessary click.

### Field types and automations

Your field choice affects what [automations](/products/pro/documenting/templates/automations/) you can build:

| Field type | Available conditions | Example |
|------------|--------------------------|---------|
| Radio buttons | Equals, not equals, contains, is empty | If "Priority" = "High" then assign to Manager |
| Dropdown | Equals, not equals, contains, is empty | If "Department" = "Finance" then show finance steps |
| Checklist | Contains, not contains, equals, is empty | If "Requirements" contains "Legal Review" then show legal step |
| Short text | Contains, equals, greater/less than, is empty | If "Country" contains "USA" then show US compliance step |
| Date | Equals, greater/less than, is empty | If "Start Date" is past today then show warning |

### Common mistakes

1. **Dropdown for binary choices** - Use radio buttons. Dropdowns add an unnecessary click for yes/no decisions.

2. **Yes/No radio buttons for a required confirmation** - A required radio field still accepts "No". Use a checklist with one item, set to **At least one item must be checked**.

3. **Long text for structured data** - Use separate short text fields or a table when you need specific pieces of information.

4. **File upload for simple confirmations** - Don't ask for an upload when ticking a one-item checklist is enough.

5. **Missing validation** - Mark required fields as required. Enable email validation on text fields that collect email addresses.
