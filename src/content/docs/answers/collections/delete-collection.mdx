## Deleting collections

This endpoint lets you permanently remove a collection and all its objects from Tallyfy Answers[^1]. This operation is irreversible and should be used with caution.

:::warning[Permanent action]
Deleting a collection permanently removes all objects within it. This can't be undone, and there's no way to recover the data once deleted.
:::

### API endpoint

```
DELETE /collections/{collection_name}
```

This endpoint needs the API key.

### Path parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `collection_name` | string | Yes | Name of the collection to delete |

### Response

The service returns a `200 OK` status code with this response:

```json
{
  "message": "Collection is deleted successfully"
}
```

It returns this even when the collection didn't exist or the delete failed, so a `200` doesn't prove anything was removed. To check, [get the collection](/products/answers/collections/get-collection/) afterwards and expect a `404`.

### Error scenarios

| Status | Description |
|--------|-------------|
| 400 | Invalid collection name format |
| 403 | The `Authorization` header is missing or doesn't match the API key |

### Example request

```bash
curl -X DELETE https://answers.tallyfy.com/collections/products \
  -H "Authorization: Bearer your_api_key"
```

### Before you delete

If a batch import is still running for the collection, stop it first with `DELETE /tasks/{collection_name}` (see [Tasks](/products/answers/tasks/)). Deleting the collection doesn't stop the import.

### When to delete a collection

Consider deleting a collection when:
- The data is no longer needed for any purpose
- You need to rebuild a collection with a different structure
- You want to remove test or development data
- You're performing cleanup of unused resources

### Alternatives to deletion

Instead of permanently deleting a collection, you might consider these alternatives:
- Export the data first with `GET /collections/{collection_name}/objects`, which returns every object's properties
- Delete every object but keep the collection with `DELETE /collections/{collection_name}/objects`
- Create a new collection with only the objects you want to keep
- Use application-level filtering to hide certain objects from users

### Best practices

- Always confirm collection names before deletion
- Consider implementing a confirmation step in your application
- Back up important data before deletion
- Use descriptive logging to track deletion operations
- Keep the API key out of anything that doesn't need it, since it can delete collections
