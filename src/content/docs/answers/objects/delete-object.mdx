## Deleting objects from collections

This endpoint permanently removes a specific object from a Tallyfy Answers collection using its unique identifier. Once deleted, you can't recover an object.

### API endpoint

```
DELETE /collections/{collection_name}/objects/{object_id}
```

This endpoint needs the API key.

### Request parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `collection_name` | path | Yes | Name of the collection containing the object |
| `object_id` | path | Yes | The object's `uid`, the identifier you set when you imported it |

### Response

The service returns a `200 OK` status code with this response:

```json
{
  "message": "Object is deleted successfully"
}
```

It deletes every object in the collection with that `uid`. It doesn't check that a matching object existed first, so a `200` doesn't prove anything was removed.

### Error scenarios

| Status | Description |
|--------|-------------|
| 400 | Invalid collection name format |
| 403 | The `Authorization` header is missing or doesn't match the API key |

### Example request

```bash
curl -X DELETE https://answers.tallyfy.com/collections/products/objects/product-123 \
  -H "Authorization: Bearer your_api_key"
```

### Important considerations

:::warning[Permanent action]
Object deletion is permanent and can't be undone. There's no "trash" or "recycle bin" for deleted objects.
:::

- Verify you have the correct `uid` before deletion
- Consider archiving objects in your application logic instead of deleting them if you might need them later
- Deleting an object removes it from search results
- To delete several objects, call this endpoint once for each. To empty a collection, `DELETE /collections/{collection_name}/objects` removes every object and keeps the collection.
- Consider implementing confirmation workflows in your application before calling this endpoint

### Alternative approaches

Instead of deleting objects, consider these alternatives:
- Add a "status" field to mark objects as inactive
- Move objects to an "archive" collection
- Implement soft deletion[^1] by adding a "deleted_at" timestamp field
